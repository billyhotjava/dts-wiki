# 03 后端设计

## 1. 包结构（JHipster 标准分层 + 自定义业务模块）

```
com.yuzhi.dts.wiki
├── config/            JHipster 生成（Security、Cache、Liquibase、Jackson…）+ WikiProperties、SchedulingConfig(ShedLock)
├── domain/            JHipster 生成的实体（勿手工改字段；改模型 = 改 JDL 重新生成）
├── repository/        JHipster 生成 + 自定义查询（页面树 CTE 等放 *RepositoryCustom / JdbcTemplate）
├── security/          JHipster 生成；自定义 KeycloakAuthorityMapper、SpaceAccessService
├── service/           JHipster 生成的实体 Service（仅管理后台使用）
│   ├── dto/, mapper/  MapStruct
│   └── wiki/          ★ 业务服务（手写）
│       ├── PageTreeService          树查询、移动、排序
│       ├── PageService              创建/保存/改名/复制/删除/恢复（事务边界）
│       ├── VersionService           历史、对比数据、恢复
│       ├── AttachmentService + BlobStore(FileBlobStore)
│       ├── CommentService / MentionService / NotificationService / WatchService
│       ├── SearchIndexService / SearchService
│       ├── ActivityService
│       ├── TemplateService
│       └── sync/                    ★ Git 同步（见 04）
│           ├── GitRepoManager       工作副本、git CLI 调用、ssh key
│           ├── InboundSyncService   git → wiki
│           ├── OutboundSyncService  wiki → git（处理 SyncOutbox）
│           ├── ConflictService      冲突检测与合并
│           ├── ImportService        首次导入
│           └── GitSyncScheduler     @Scheduled + @SchedulerLock
└── web/rest/          JHipster 生成的实体 Resource（**仅 ROLE_ADMIN**）
    └── wiki/          ★ 业务 REST（手写）：/api/wiki/**
```

规则：
- **生成代码尽量不改**；需要改的只改 `security/SecurityUtils` 的权限提取、`SecurityConfiguration` 的路径授权（见 §3），并在文件头注释 `// DTS-WIKI: customized` 便于重新生成时合并。
- 业务 REST 只调用 `service/wiki/**`，不直接调用生成的实体 Service（后者没有空间权限校验）。
- 用 ArchUnit（JHipster 自带 `TechnicalStructureTest`）增加规则：`web.rest.wiki..` 不得依赖 `repository..`。

## 3. 身份与权限

### 3.1 Keycloak → 应用权限（authorities）
Keycloak 在 client `dts-wiki` 上新增映射器（06 §3）：把用户的 **dts-wiki 客户端角色** 写入 ID token / userinfo 的 `roles` 声明（不加前缀）。
自定义 `KeycloakAuthorityMapper`（在 JHipster `SecurityUtils.extractAuthorityFromClaims` 中调用）：

| `roles` 中的值 | 应用 authority |
|----------------|----------------|
| `reader` | `ROLE_USER` |
| `editor` | `ROLE_EDITOR` |
| `admin` | `ROLE_ADMIN` |
| `space-<slug>` | `ROLE_SPACE_<SLUG>`（大写，连字符换下划线） |

JHipster 生成代码只识别 `ROLE_` 开头的值，因此必须做上述映射（`AuthoritiesConstants` 增加 `EDITOR`）。

### 3.2 空间访问（`SpaceAccessService`）
- `canRead(space)` = `ROLE_ADMIN` ∨ `ROLE_SPACE_<SLUG>`
- `canWrite(space)` = `canRead` ∧ (`ROLE_EDITOR` ∨ `ROLE_ADMIN`)
- `readableSpaceIds()`：供列表、检索、最近更新、@提及候选做 SQL 过滤（**过滤写在查询里**，不在返回后过滤）。
- 无权访问与不存在一律返回 **404**（不泄露存在性）；已知可读但无写权限返回 **403**。

### 3.3 路径授权（`SecurityConfiguration`）
```
/api/wiki/**            authenticated（细粒度由 SpaceAccessService）
/api/admin/**、生成的实体资源 /api/spaces|pages|page-versions|...   hasAuthority(ROLE_ADMIN)
/management/health/**   permitAll（仅健康检查）
/management/**          ROLE_ADMIN
```

## 4. 业务 REST API（`/api/wiki`，JSON，错误用 JHipster ProblemDetail + `errorKey`）

### 空间与页面树
| 方法 | 路径 | 请求 → 响应 |
|------|------|-------------|
| GET | `/spaces` | → `[SpaceSummary{slug,name,description,pageCount,updatedAt,syncStatus}]`（仅可读） |
| GET | `/spaces/{slug}` | → `SpaceDetail{…, rootPageId, syncRoots[{repoPath, mountPageId}]}` |
| GET | `/spaces/{slug}/tree?depth=` | → `[TreeNode{id,title,kind,hasChildren,syncStatus,children[]}]`（depth 默认全树） |
| GET | `/spaces/{slug}/resolve?path=` | 仓库相对路径或旧站 URL 路径 → `{pageId}`（相对链接、旧链接跳转用） |

### 页面
| 方法 | 路径 | 请求 → 响应 |
|------|------|-------------|
| GET | `/pages/{id}` | → `PageView{id,spaceSlug,title,kind,contentMd,versionNo,updatedAt,updatedBy,gitPath,gitRepoUrl,gitCommit,syncStatus,breadcrumbs[{id,title}],labels[],watching,editable}` |

| PUT | `/pages/{id}/content` | `{baseVersionNo,contentMd,message?}` → 200 `{versionNo}`；409 `PAGE_VERSION_CONFLICT {currentVersionNo}`；409 `PAGE_SYNC_CONFLICT`（存在未解决同步冲突时禁止普通保存） |
| PATCH | `/pages/{id}` | `{title?,parentId?,position?}` → 200 `PageView`（改名/移动） |
| POST | `/pages/{id}/copy` | `{targetParentId,title?}` → 201 `PageView` |
| DELETE | `/pages/{id}` | → 204（进回收站，子树一并） |
| POST | `/pages/{id}/restore` | → 200（从回收站恢复） |
| GET | `/spaces/{slug}/trash` | → 回收站列表 |
| PUT | `/pages/{id}/draft` · GET · DELETE | 服务端草稿 `{contentMd,baseVersionNo}` |
| POST | `/pages/{id}/editing` | 编辑心跳 → `{editors:[{login,name}]}`（内存 TTL 90 s） |
| PUT | `/pages/{id}/labels` | `{names[]}` |
| PUT/DELETE | `/pages/{id}/watch` | 关注 / 取消关注 |

## 5. 事务与一致性
- 页面变更、版本写入、检索文档、outbox、活动、通知**同一事务**提交；git 推送在事务外异步进行。
- 并发保存用 `baseVersionNo` 乐观校验，并在 `page` 行上 `SELECT … FOR UPDATE` 防止同一页并发写入产生重复版本号。
- 页面树移动：校验 I5/I6 后批量更新子树中 GIT/FOLDER 页的 `gitPath`（前缀替换），并写一条 `MOVE` outbox（出站用 `git mv` 移动整个目录）。

## 6. 定时任务（`@Scheduled` + ShedLock）

| 任务 | 周期 | 说明 |
|------|------|------|
| `GitSyncScheduler.run` | 30 s | 对每个启用同步的空间：先出站（处理 outbox）再入站（fetch + 导入变更），见 04 |
| `TrashPurgeJob` | 每日 03:30 | 物理删除超过保留期的软删除页面与附件文件 |
| `DraftCleanupJob` | 每日 | 清理 30 天未更新的草稿 |
| `NotificationDigestJob` | 5 min | 邮件通知聚合发送（SMTP 未配置则跳过） |

## 7. 其他实现要点
- Markdown → 检索纯文本：CommonMark-java 解析后取文本节点（去掉代码块语言标记、链接 URL 保留文字）。
- 文件名生成（新建/改名 GIT 页）：`标题` → 替换 `/\:*?"<>|` 与控制字符为 `-`，去首尾空白与点，限长 120；同目录重名追加 `-2`、`-3`；保持中文（与 sprint-workflow `T{NN}-{中文名}.md` 兼容）。
- 渲染由前端完成；后端只存、只检索 Markdown 原文。
- 日志：JSON（logstash encoder，JHipster 自带），带 `traceId`、`user`、`space`；不记录页面正文。
