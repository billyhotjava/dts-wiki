# 06 部署与运维

## 1. 环境约束（10.20.0.50，务必遵守）
- RHEL 8.10 + Docker 26.1 + compose v2.27；**docker daemon 代理配置损坏，`docker pull` 不可用**：镜像在开发机构建，`docker save | gzip | ssh root@10.20.0.50 'gunzip | docker load'` 传输。
- **不得重启 dockerd**（live-restore 关闭，会连带重启 Jira、Keycloak、现网 wiki）。
- 可达：GitHub（仅 SSH 22，HTTPS 不通）、npmmirror；Maven 依赖在开发机构建时解决。
- 已有服务端口：18000/19443（portainer）、18080（jira）、18081（keycloak）、18090（现网 wiki）、5432（jira 的 PG）。**新 wiki 用 18091**。

## 2. 镜像

### 2.1 wiki-app
JHipster 默认用 Jib，但同步功能需要容器内有 `git` 与 `ssh`，改用 Dockerfile（放 `src/main/docker/app.Dockerfile`）：
```dockerfile
FROM eclipse-temurin:25-jre-noble
RUN apt-get update && apt-get install -y --no-install-recommends git openssh-client tzdata \
 && rm -rf /var/lib/apt/lists/* && useradd -r -u 1001 -m wiki
ENV TZ=Asia/Shanghai JAVA_OPTS="-XX:MaxRAMPercentage=60 -XX:+ExitOnOutOfMemoryError"
COPY target/dts-wiki-*.jar /app/app.jar
USER wiki
EXPOSE 8080
ENTRYPOINT ["sh", "-c", "exec java $JAVA_OPTS -jar /app/app.jar"]
```
构建：`./mvnw -Pprod clean verify && docker build -f src/main/docker/app.Dockerfile -t dts-wiki-app:<git-sha> .`

前端打包（D14）：`pom.xml` 的 `prod` profile 配置 `frontend-maven-plugin`：`install-node-and-pnpm`（Node 24 LTS，npm registry 用 npmmirror）→ `pnpm install --frozen-lockfile` → `pnpm build`（工作目录 `frontend/`）→ `maven-resources-plugin` 把 `frontend/dist/` 复制到 `target/classes/static/`。开发期不走 Maven：`cd frontend && pnpm dev`（Vite 5173，代理 `/api`、`/oauth2`、`/login`、`/logout` 到 8080）。

### 2.2 wiki-db
PostgreSQL 18 + 检索扩展（F0 spike 确定 `pg_bigm` 或 `zhparser`），`src/main/docker/postgres.Dockerfile` 多阶段编译扩展，镜像名 `dts-wiki-db:18-<扩展>`。

## 3. Keycloak 变更（realm `yuzhicloud`，client `dts-wiki`；脚本化放 `deploy/keycloak/wiki-v2.sh`，幂等）
1. 增加回调：`http://10.20.0.50:18091/login/oauth2/code/oidc`（验收期）、`https://wiki.yuzhicloud.com/login/oauth2/code/oidc`（上线）；`post.logout.redirect.uris` 增加相应站点。
2. 新增协议映射器 `client-roles-to-roles`：类型 *User Client Role*，client = `dts-wiki`，claim `roles`，多值，加入 ID token / access token / userinfo，**无前缀**。
3. 角色与组沿用现网：`reader`（realm 默认角色）、`editor`（组 研发部、管理员）、`admin`（组 管理员）、`space-dts`（组 产品-DTS 平台）、`space-prs`（组 产品-PRS 花卉租赁）。新建空间时按 03 §4 `/admin/spaces` 流程或 dts-rdc `deploy/sso/apps/wiki-spaces.sh` 补建角色与组。
4. client secret 复用现网（在 .50 `/data/dts-wiki/.env` 的 `WIKI_OIDC_CLIENT_SECRET`），拷贝到新 `.env`。

## 4. 部署编排（`/data/dts-wiki-v2/compose.yml`，模板放仓库 `deploy/compose.yml`）

```yaml
name: dts-wiki-v2
services:
  wiki-db:
    image: dts-wiki-db:18-bigm
    restart: unless-stopped
    environment: { POSTGRES_DB: wiki, POSTGRES_USER: wiki, POSTGRES_PASSWORD: ${WIKI_DB_PASSWORD} }
    volumes: [ "./db:/var/lib/postgresql" ]
    healthcheck: { test: ["CMD-SHELL", "pg_isready -U wiki -d wiki"], interval: 10s, retries: 10 }
  wiki-app:
    image: dts-wiki-app:${APP_TAG}
    restart: unless-stopped
    depends_on: { wiki-db: { condition: service_healthy } }
    ports: [ "18091:8080" ]
    environment:
      SPRING_PROFILES_ACTIVE: prod
      SPRING_DATASOURCE_URL: jdbc:postgresql://wiki-db:5432/wiki
      SPRING_DATASOURCE_USERNAME: wiki
      SPRING_DATASOURCE_PASSWORD: ${WIKI_DB_PASSWORD}
      SPRING_LIQUIBASE_URL: jdbc:postgresql://wiki-db:5432/wiki
      SPRING_SECURITY_OAUTH2_CLIENT_PROVIDER_OIDC_ISSUER_URI: https://sso.yuzhicloud.com/realms/yuzhicloud
      SPRING_SECURITY_OAUTH2_CLIENT_REGISTRATION_OIDC_CLIENT_ID: dts-wiki
      SPRING_SECURITY_OAUTH2_CLIENT_REGISTRATION_OIDC_CLIENT_SECRET: ${WIKI_OIDC_CLIENT_SECRET}
      SERVER_FORWARD_HEADERS_STRATEGY: framework
      APPLICATION_WIKI_PUBLIC_URL: ${WIKI_PUBLIC_URL}     # 验收期 http://10.20.0.50:18091，上线后 https://wiki.yuzhicloud.com
      TZ: Asia/Shanghai
    volumes:
      - ./repos:/data/repos
      - ./secrets:/data/secrets
      - ./attachments:/data/attachments
```
- 目录归属：`repos/`、`secrets/`、`attachments/` 属主 uid 1001（容器内 wiki 用户）；`secrets/*.key` 权限 0600。
- `.env` 不入库；仓库提供 `deploy/.env.example`。

## 5. 备份与恢复
- 复用 dts-rdc `deploy/sso/backup/` 的模式：`wiki-db` 每日 03:20 `pg_dump -Fc` → `/data/backup/wiki/`，`pg_restore --list` 校验，保留 14 份，systemd timer。
- 附件：每日 `rsync -a --link-dest` 快照到 `/data/backup/wiki-attachments/<日期>/`，保留 14 份（内容寻址，增量极小）。
- 研发文档另有 git 远端这一份副本；wiki 原生页（NATIVE）建议每日导出为 Markdown 推送到只读仓库 `dts-wiki-native-backup`（待需求方确认，Sprint-6 Q2）。
- 上线前做一次恢复演练：还原到临时库，页面数、版本数与生产一致。

## 6. 上线切换与回退
**切换前置**：新 wiki 在 18091 验收通过（07 §5 验收脚本）；现网 wiki 中网页编辑的本地提交已推送到 GitHub（需要 dts-rdc 写权限 deploy key）。

步骤：
1. 现网 wiki 置为只读（停止 `dts-wiki-api` 容器即可禁止编辑；静态站点仍可访问）；
2. 新 wiki 对 dts、prs 空间执行一次"立即同步"，核对页面数；
3. Keycloak `dts-wiki` 确认已有 `https://wiki.yuzhicloud.com/login/oauth2/code/oidc` 回调；新 wiki `.env` 改 `WIKI_PUBLIC_URL=https://wiki.yuzhicloud.com` 并重启；
4. 阿里云 `/etc/nginx/conf.d/wiki.yuzhicloud.com.conf`：`proxy_pass http://10.20.0.50:18090;` → `proxy_pass http://10.20.0.50:18091;`，`nginx -t && systemctl reload nginx`；
5. 验证：登录、打开旧书签（下表）、编辑一次并确认 git 提交；
6. 现网 wiki 容器 `docker compose stop`（保留 30 天，不删数据卷）。

回退：第 4 步改回 18090 并启动现网 `dts-wiki-api`；新 wiki 期间的网页编辑已推送到 GitHub，现网工作仓库 `git pull` 即可同步，不丢数据。

旧链接映射（前端 Redirect 组件 + `/api/wiki/spaces/{slug}/resolve`）：

| 旧 URL | 仓库路径 | 新空间 |
|--------|----------|--------|
| `/p/dts/docs/<rel>`、`/docs/<rel>` | `docs/<rel>.md` 或 `docs/<rel>/README.md` | dts |
| `/p/dts/worklog/<rel>`、`/worklog/<rel>` | `worklog/<rel>.md` 或 `.../README.md` | dts |
| `/p/prs/worklog/<rel>` | `worklog/<rel>...`（prs-stack） | prs |
| `/sandbox/<rel>` | — | 练习区（按标题匹配） |

## 7. 可观测性与告警
- 健康检查：`/management/health/liveness`、`/management/health/readiness`（compose healthcheck 使用后者）。
- 指标：Micrometer（JHipster 自带 `/management/prometheus`，`ROLE_ADMIN`），自定义 `wiki_sync_outbox_pending`、`wiki_sync_conflicts_open`、`wiki_sync_last_success_seconds`。
- 告警（先用日志 + 状态页，后续接 Grafana）：某空间连续 10 分钟同步失败、outbox 失败条目 > 0、磁盘使用 > 80%。
- runbook（`docs/runbook.md`）：启停、同步卡住、冲突积压、deploy key 失效、恢复备份、回退切换。
