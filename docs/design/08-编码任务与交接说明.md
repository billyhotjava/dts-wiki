## 3. 硬性约束
- **实体模型只改 JDL**，再用生成器重新生成；生成代码中必须手改的地方加注释 `// DTS-WIKI: customized` 并在提交信息中说明。
- 业务接口只在 `/api/wiki/**`，全部经 `SpaceAccessService`；生成的实体接口仅 `ROLE_ADMIN`。
- git 操作只允许出现在 `service.wiki.sync` 包；禁止 `push --force`；写入路径必须在同步根白名单内。
- 版本不可变；内容相同不产生新版本（sha256 比较）。
- .50：不得 `docker pull`（不可用）、不得重启 dockerd、不得改动现网 wiki（`/data/dts-wiki`、端口 18090）与 Jira/Keycloak 容器；新 wiki 只用 `/data/dts-wiki-v2` 与端口 18091。
- 密钥（`.env`、deploy key、client secret）不入库；`.gitignore` 覆盖 `.env`、`deploy/secrets/`。
- 版本原则（DTS R-012）：只用正式版；新增依赖检查许可证（OSI 许可；AGPL 等强传染许可证需需求方确认）。

## 4. 约定
- 分支：`main` 受保护，功能分支 `feat/W<n>-<简述>`，合并前 CI 绿。
- 提交信息：`feat(F3/T02): 页面阅读与面包屑`（type + Sprint-6 Task 编号）。
- 语言：与需求方沟通用中文；代码注释与文档用英文；界面文案走 i18n（zh-cn 为默认）。
- 每个工作包结束：更新 Task 文档状态（DRAFT→IN_PROGRESS→DONE），证据（命令输出、截图、提交 sha）写入 `sprint-6-202610/it/`。
