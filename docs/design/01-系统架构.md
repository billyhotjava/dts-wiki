# 01 系统架构

## 1. 组件

```
                        ┌──────────────────────────── 10.20.0.50 (docker compose, /data/dts-wiki-v2) ─────────────────────────┐
浏览器 ─HTTPS─► 阿里云 nginx ─WireGuard─► │ wiki-app  :8080 (host 18091)                                                           │
 (wiki.yuzhicloud.com)  (TLS 终止)        │   JHipster 单体 jar：React 前端静态资源 + /api + /oauth2 + /login                        │
                                          │   ├─ 页面/空间/版本/附件/评论/通知/检索 服务                                             │
                                          │   ├─ GitSync（ShedLock 单实例）── git CLI ──► /data/dts-wiki-v2/repos/<repo>  ──ssh──► GitHub │
                                          │   └─ BlobStore ──► /data/dts-wiki-v2/attachments                                        │
                                          │ wiki-db   PostgreSQL 18 (+pg_bigm)  数据 /data/dts-wiki-v2/db，不暴露端口                 │
                                          └───────────────────────────────────────────────────────────────────────────────────────┘
                     Keycloak（现网 https://sso.yuzhicloud.com，realm yuzhicloud，client dts-wiki）
```

- 单体、单实例部署（v1）。所有定时任务用 ShedLock 加锁，保证将来多实例时仍只执行一次。
- 前端由 jar 内置提供（JHipster 生产构建），**不需要单独的 nginx**；TLS 在阿里云边缘终止。
- 应用设置 `server.forward-headers-strategy=framework`，以便在代理后生成正确的 `https://wiki.yuzhicloud.com/...` 回调地址。

## 2. 登录流程（JHipster oauth2）

```
浏览器 GET /s/prs/pages/42
  → 前端请求 /api/account → 401
  → 前端整页跳转 /oauth2/authorization/oidc
  → Keycloak 登录（已登录 Jira/现网 wiki 则免登）
  → 回调 /login/oauth2/code/oidc → Spring Security 建立服务端会话（JSESSIONID，HttpOnly，Secure）
  → UserService 按 token 同步 jhi_user（login、姓名、邮箱、语言）与权限
  → 回到原页面
```

- Keycloak client `dts-wiki` 需新增回调：`http://10.20.0.50:18091/login/oauth2/code/oidc`（验收期）、`https://wiki.yuzhicloud.com/login/oauth2/code/oidc`（上线）。
- 登出：JHipster 默认 `POST /api/logout` 返回 Keycloak `end_session_endpoint`，前端跳转；`post_logout_redirect_uri` 为站点首页。

## 3. 请求处理（以保存页面为例）

```
PUT /api/wiki/pages/42 {baseVersionNo: 7, contentMd: "...", message: "..."}
  WikiPageResource
   → SpaceAccessService.checkWrite(user, page.space)          // 403 / 404
   → PageService.saveContent(...)                              // @Transactional
       · 比对 baseVersionNo 与 page.currentVersion.versionNo → 不一致 409 PAGE_VERSION_CONFLICT
       · content sha256 未变 → 直接返回当前版本（不产生新版本、不同步）
       · 新增 PageVersion(versionNo=8, source=WEB, author=当前用户)
       · page.currentVersion = v8；page.syncStatus = PENDING_PUSH（仅 GIT 页）
       · SearchIndexService.upsert(page)                     // 同事务更新 page_search_doc
       · SyncOutbox.add(WRITE, page, v8, actor)               // 同事务（仅 GIT 页）
       · ActivityService.record(PAGE_UPDATED) / NotificationService.notifyWatchers(...)
   → 200 {versionNo: 8, ...}
GitSyncScheduler（每 30 s）→ 处理 outbox → commit(author=用户) → rebase → push → page.syncStatus = SYNCED
```

## 4. 与现网系统的关系

| 现网组件 | 处置 |
|----------|------|
| `dts-rdc/wiki/` 静态站点 + `deploy/wiki/`（oauth2-proxy + nginx + Node wiki-api，.50:18090） | 验收期并行运行；切换后停止，保留 30 天用于回退 |
| 现网 `.50:/data/dts-wiki/repo` 中尚未推送到 GitHub 的网页编辑提交 | **切换前必须推送到 GitHub**（需要 deploy key），再做新 wiki 的首次导入 |
| Keycloak client `dts-wiki` 及其角色/组 | 沿用；新增回调地址与"客户端角色 → roles"映射器（见 06） |
| `dts-rdc/products.json` 产品注册表 | 仅用于首次导入时创建空间；之后空间配置以新 wiki 数据库为准 |
